# Progetto Build

Cinematic architectural-portfolio site for Progetto Build — Design |
Renovation | Build, serving South Florida (Pompano Beach, Fort
Lauderdale, Lauderdale-by-the-Sea, Broward County).

Built with React + TypeScript + Vite, Tailwind CSS, GSAP/ScrollTrigger for
scroll-scrubbed cinematic transformations, Framer Motion for
micro-interactions, and React Three Fiber for one shader-driven WebGL
photo transition. Every "before/after" photo on the site is real jobsite
and finished photography, programmatically cropped from the client's own
composite files — see [`PROCESSING.md`](./PROCESSING.md).

## Getting started

```bash
npm install
npm run dev       # local dev server
npm run build     # type-check + production build to dist/
npm run preview   # serve the production build locally
npm run lint
```

### The transformation engine (`src/components/transformation/`)

No per-object photo segmentation exists in the source material (no
isolated, alpha-cut furniture cutouts), so every strategy here treats a
whole real photograph as one "layer" and moves it with 3D perspective
transforms — never a fabricated object, never a plain opacity crossfade:

- **`TransformationScene`** — GSAP ScrollTrigger–pinned (flagship) or
  in-flow (gallery) scrub timeline. Swings the BEFORE photo away in 3D
  (translateX/Z, rotateY, scale) while the AFTER photo settles into frame
  beneath it. Used for the `"layered"` strategy (two real photo angles of
  the same room, staggered) and `"masked"` strategy (single photo pair).
- **`WebGLTransformScene` / `WebGLPlane`** — the one place Three.js/R3F
  earns its keep: a shader-driven cross-dissolve between the two real
  photo textures (`"webgl-plane"` strategy), rendered on demand
  (`frameloop="demand"`) so it costs nothing between scroll ticks.
- **`PhotoLayer`** — a single before/after photo pair rendered as two
  `.tf-before` / `.tf-after` planes for the CSS engine above to animate.
- **`StageIndicator`** — the restrained mono "01 EXISTING … 05 FINISHED"
  readout + progress fill, updated imperatively (no React re-render per
  scroll tick) so a 60fps scrub never triggers a re-render storm.

All three strategies are driven entirely by scroll position (`scrub`,
never autoplay) and fall back, under `prefers-reduced-motion` or on
mobile, to progressively simpler treatments — see `src/lib/useIsMobile.ts`
/ `useReducedMotion.ts` and the mobile branch inside each scene.

### Other key components

- `Hero` — full-bleed real photograph (the strongest single frame in the
  set), subtle GSAP scroll parallax + a one-time Framer Motion entrance.
- `FlagshipSection` — the three flagship cinematic transformations.
- `SelectedProjects` / `GalleryTile` — the editorial photography gallery
  (masonry from each photo's real aspect ratio) covering the remaining
  rooms; the old drag-slider comparison is gone — a real photo is shown
  large, with a small explicit "View Before" toggle as the only secondary
  compare interaction (Framer Motion crossfade, not a drag handle).
- `LoadingScreen` — short mask-reveal loader, skipped entirely under
  reduced motion.
- `AIProjectAssistant` — bottom-right guided consultation panel. No
  backend is simulated; `submitConsultation()` in that file is the single
  integration point to wire to a real CRM/endpoint.
- `Reveal` — shared scroll-reveal wrapper (fade + rise).

## Design system

Colors (`#090909` / `#111111` surfaces, warm beige/stone/gold accents),
Instrument Serif + Inter + JetBrains Mono, and the clamp()-based type
scale all come directly from the client's brand spec, cross-checked
against the `ui-ux-pro-max` skill's luxury real-estate/architecture
recommendations. The gold accent is tuned to the client's actual logo
color (extracted from `assets_raw/progetto_build_logo_traced.png`).
